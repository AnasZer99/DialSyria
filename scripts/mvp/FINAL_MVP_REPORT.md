## 6. منع التكرار والحارس اليومي (بعد التحسين)

- الحارس يقرأ **آخر تشغيل** لليوم الدمشقي: يتخطى فقط إذا كان `feeds_fail = 0`.
- التشغيل الجزئي (فشل مصدر) **يجوز إعادته** في اليوم نفسه؛ التكرار مستبعد عبر تطبيع الرابط + UNIQUE.
- `force` متاح للإدارة اليدوية فقط.

## 7. البريد والنشر

- **البريد:** Resend → Brevo → Mock. لا مفاتيح مضبوطة؛ الحالة `EMAIL_PROVIDER_SETUP_REQUIRED`. لم يُرسل أي بريد حقيقي.
- **Telegram/Beta:** بقي معزولًا ولم يُفعَّل؛ لا إرسال حقيقي.
- **النشر:** لم يُنشر شيء، ولا migration بعيدة، ولا تغيير على Pages/Workers/Staging.
- **Git:** لم يُنشأ الفرع ولم يُدفع شيء؛ كل العمل محفوظ في الشجرة العاملة.

## 8. جاهزية Staging (قائمة قصيرة)

1. تعديل `cron-worker/index.js` + `wrangler.jsonc` (يومي + ساعي، بلا `/api/direct`).
2. إضافة جدول/فهارس `schema.sql` (أو تطبيق ترحيل 0014 على قاعدة جديدة).
3. نقل `scripts/mvp/` → `docs/mvp/`.
4. `git checkout -b feat/rss-mvp-simplification` + commit + push للفرع فقط (بعد التأكد أن الدفع لا يفعّل نشرًا إنتاجيًا).
5. نشر Pages + تطبيق ترحيل 0014 على قاعدة Staging مع نسخة احتياطية (يتطلب موافقة منفصلة).
6. (اختياري) `RESEND_API_KEY` + `EMAIL_FROM` + نطاق موثّق لاختبار بريد حقيقي.

## 9. المخاطر المتبقية (بالأولوية)

1. صلاحيات Git تمنع حفظ العمل في فرع — الخطر الأكبر الآن.
2. جدول Cron الفعلي ما زال `*/30` (الحارس اليومي يخفف الأثر، لكنه ليس الجدول المطلوب).
3. تغطية تقنية/ثقافة سورية ضعيفة (قياس موثق).
4. سانا متقطعة الوصول (فشل متوقع يُسجَّل ويُعاد غدًا).
5. فهارس `articles` غائبة حتى تعديل `schema.sql` (أداء مقبول حاليًا).
6. `tests/zz-live-audit-probe.test.mjs` اسم غير وصفي لاختبار كتالوج حقيقي.
