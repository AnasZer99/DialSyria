# DialSyria — خيارات التوسع الوطني (تقرير خيارات فقط)

**الحالة:** تقرير قرار، لا تنفيذ. الأرقام المذكورة إشارية وتحتاج تحققًا لحظة القرار.

## 1. حدود جمع أخبار سوريا

- **المصادر المباشرة محدودة**: عدد الناشرين السوريين الذين يقدمون RSS حديثًا صغير (سانا، تلفزيون سوريا، نورث برس حاليًا). عنب بلدي وأثر لهما RSS متوقف.
- **التغطية المتخصصة ناقصة**: لا RSS سوري مخصص للاقتصاد/التقنية/الرياضة/الصحة/الثقافة؛ التصنيف يعتمد على عناوين التغذيات العامة.
- **البديل الأسلم قبل التوسع**: إما (أ) مصادر إقليمية عربية تغطي سوريا، أو (ب) Google News كطبقة استدراك مع حلّ رابط الناشر الأصلي والتحقق من الهوية، أو (ج) Telegram للمؤسسات (مثل نموذج Beta) — كلها تحتاج اختبار تغطية قبل التبني.

## 2. زيادة المصادر والتصنيفات والمناطق

- إضافة 10–20 تغذية سورية/عربية مع فحص حي أسبوعي (HTTP + حداثة + ملاءمة عينة).
- مراقبة الانحراف: نسبة الأقسام الفارغة، نسبة الأخبار المكررة، معدل فشل المصادر.
- تقسيم جغرافي أدق (محافظات) يتطلب حقلًا جديدًا + واجهة تصفية؛ لا يُضاف قبل وجود تغطية فعلية لكل محافظة.
- تكلفة التشغيل تبقى منخفضة (D1 + Cron) لكن حدود Cloudflare Free تفرض تقسيم الجمع إلى دفعات أو أكثر من دورة.

## 3. تكلفة البريد عند تجاوز الخطة المجانية

- Resend المجاني المعروف: 3,000 رسالة/شهر بحد 100/يوم (تحقق من الوثائق الرسمية وقت القرار).
- 100 مشترك × نشرة يومية = ~3,000 رسالة/شهر ⇒ عند الحد المجاني تقريبًا.
- 500 مشترك ≈ 15,000 رسالة/شهر ⇒ خطة مدفوعة (الأسعار تتغير؛ تُطلب عروض عند القرار).
- بدائل: Brevo، Amazon SES (أرخص عند الحجم الكبير لكن إعداد نطاق/سمعة أدق)، Postmark (جودة تسليم أعلى، سعر أعلى).
- تكلفة إضافية غير مباشرة: توثيق النطاق (SPF/DKIM/DMARC)، صفحات إلغاء اشتراك، معالجة Bounce/Complaint.

## 4. WhatsApp Business API

- النموذج الرسمي (Meta Cloud API عبر مزود مثل Twilio/360dialog) يتطلب: حساب أعمال موثّق، رقمًا مخصصًا، قوالب رسائل معتمدة، وفاتورة لكل محادثة/رسالة (تسعير متغير حسب الدولة وفئة المحادثة).
- الكلفة تتغير شهريًا؛ لا يمكن تقديم رقم ثابت دون عرض من مزود.
- قيود: لا إرسال تسويقي بلا موافقة صريحة، وسياسات Meta صارمة قد توقف الرقم.
- التوصية: لا WhatsApp قبل إثبات الطلب على البريد وتثبيت جودة المحتوى.

## 5. طرق الدفع مستقبلًا (السوق السوري)

- **العائق الأساسي**: محدودية بوابات الدفع الدولية في سوريا، وقيود التحويل، ومتطلبات KYC.
- خيارات عملية محتملة: (أ) اشتراك عبر مزود خارجي/وسيط مرخّص، (ب) بطاقات مسبقة الدفع/رموز تفعيل تُشترى محليًا، (ج) تحويلات عبر شركات حوالات مع تسوية يدوية (تكلفة تشغيلية عالية)، (د) دفع بحساب بنكي في بلد العبور.
- كل خيار يتطلب مراجعة قانونية وضريبية في بلد التسجيل وبلد التحصيل؛ لا يُنفّذ شيء دون استشارة.
- الحد الأدنى للمنتج قبل الدفع: قيمة محتوى مثبتة + احتفاظ مشتركين + تكلفة بريد معروفة.

## 6. قيود Cloudflare عند النمو

- **D1 Free**: حدود قراءة/كتابة يومية وحدود استعلام؛ التوسع في الزوار يتطلب كاشًا أقوى (ISR/Edge Cache) أو خطة مدفوعة.
- **Workers Free**: سقف subrequests لكل استدعاء — يؤثر على الجمع عند كثرة المصادر؛ الحل: دفعات/عامل إضافي/خطة مدفوعة.
- **Pages**: حدود بناء ونطاق ترددي؛ مع الصور/الخطوط المحلية الحالية لا مشكلة قريبة.
- **KV/R2** غير مستخدمة حاليًا؛ قد تلزم للتخزين المؤقت بعيد المدى.

## 7. الخصوصية والاحتفاظ

- تخزين البريد + المواضيع + ساعة التسليم + سجل النشرات (`digests`). لا حاجة لبيانات أكثر.
- الاحتفاظ بالمقالات 14 يومًا (قابل للتعديل)؛ سجل الجمع يُقلَّم دوريًا.
- مطلوب قبل التوسع: سياسة خصوصية منشورة، آلية حذف حساب/بيانات، سجل موافقة، وتوثيق معالجة بيانات البريد لدى المزود.
- لا تُخزَّن عناوين IP أو محتوى شخصي إضافي بلا حاجة.

## 8. ما ينبغي قياسه قبل التوسع الوطني

1. عدد المشتركين النشطين أسبوعيًا ومعدل الفتح (إن توفر).
2. نسبة الأيام التي وصلت فيها نشرة غير فارغة لكل مشترك.
3. تغطية كل قسم/موضوع: عدد الأخبار الفريدة يوميًا والأيام الفارغة.
4. معدل فشل المصادر وزمن الاستجابة.
5. تكلفة البريد الفعلية لكل مشترك/شهر.
6. معدل إلغاء الاشتراك بعد الإرسال.
7. زمن تحميل الصفحة الأساسية (موبايل) وتحويل الزائر إلى مشترك.

**الخلاصة:** التوسع الآمن يبدأ بزيادة المصادر السورية المتحقق منها وتثبيت جودة النشرة البريدية؛ WhatsApp والدفع مؤجّلان حتى وجود طلب مثبت ومسار قانوني واضح.
