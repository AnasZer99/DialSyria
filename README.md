# DialSyria — ديل سيريا

نشرة أخبار يومية بالاشتراك: أخبار سوريا والعالم تُجمع وتُصنّف تلقائياً، وتصل إلى بريد المشترك كل يوم في الساعة التي يختارها. عربية أولاً مع دعم كامل للإنجليزية، تصميم موبايل أولاً بروح "الصحيفة الرقمية".

**الموقع الحي:** https://dial-syria.pages.dev — **لوحة الإدارة:** https://dial-syria.pages.dev/admin

## البنية (كلها ضمن الخطة المجانية على Cloudflare)

- **Frontend**: React 19 + Vite (SPA، RTL/LTR، خطوط Amiri + Cairo مستضافة ذاتياً)
- **Backend**: Cloudflare Pages Functions (`functions/api/*`)
- **قاعدة البيانات**: Cloudflare D1 — `dialsyria-db`
- **مصادر الأخبار**: RSS (Google News استعلامات لكل موضوع + BBC عربي + عنب بلدي) → تصنيف بالكلمات المفتاحية → إزالة التكرار → تخزين
- **الإرسال**: Brevo API (مجاني 300 بريد/يوم) — نشرة HTML بتصميم تحريري لكل مشترك حسب لغته
- **المجدول**: Worker منفصل `dialsyria-cron` — تجميع كل 20 دقيقة، إرسال النشرات عند الساعة :07 لكل ساعة (توقيت دمشق)
- **الدخول**: رابط سحري بالبريد بدون كلمات مرور · **الإدارة**: كلمة مرور في متغيرات البيئة

## متغيرات البيئة (Pages → Settings → Variables)

| المتغير | الوظيفة | ملاحظات |
|---|---|---|
| `ADMIN_PASSWORD` | دخول لوحة الإدارة | مضبوط بالفعل — القيمة في `.dev.vars` المحلي |
| `CRON_SECRET` | حماية `/api/ingest` و`/api/digest` | مضبوط بالفعل |
| `BREVO_API_KEY` | إرسال النشرات | **أضفه عندك** (انظر أدناه) |
| `SENDER_EMAIL` | بريد المُرسِل | بريد موثّق في Brevo |

## تفعيل البريد (خطوتان، مجاني)

1. حساب مجاني على [Brevo](https://www.brevo.com) → SMTP & API → إنشاء مفتاح API
2. في Brevo: Senders → إضافة بريدك والنقر على رابط التوثيق الذي يصلك
3. في Cloudflare Pages → dial-syria → Variables:
   - `BREVO_API_KEY` = المفتاح
   - `SENDER_EMAIL` = بريدك الموثّق

قبل إضافة المفتاح: روابط الإدارة تظهر مباشرة في الواجهة (وضع التطوير). بعدها تصلك بالبريد فقط.

## الأوامر

### تجربة محلية فورية

شغّل `npm run demo` من الطرفية باستخدام Node.js يدعم `--use-system-ca` و`node:sqlite` (تم التحقق باستخدام 22.17) والتبعيات المثبتة. يستخدم الأمر شهادات النظام الموثوقة مع استمرار التحقق من TLS، ويجلب أخبار RSS الحقيقية الحالية ويعرض المصادر والروابط والتواريخ وأخطاء التغذيات. بعض روابط Google News وسيطة. يستخدم مشتركًا تجريبيًا وقاعدة بيانات في الذاكرة؛ لا يحتاج Brevo أو قاعدة D1 بعيدة. لا يشغّل الموقع أو المجدول.

لإرسال عينة اختيارية، جهّز بوت Telegram مخصصًا للاختبار من دون webhook نشط، وافتح محادثة خاصة معه. أدخل الرمز في الطرفية عند الطلب؛ لن يظهر أثناء الكتابة ولن يُحفظ. أرسل للبوت رسالة التحقق التي يعرضها البرنامج، ثم راجع النشرة واكتب `SEND` فقط إذا رغبت بإرسال رسالة حقيقية واحدة. يتطلب ذلك اتصالًا بـ Telegram. عند تشغيل الأمر دون طرفية تفاعلية يعرض نتائج RSS ويتجاوز Telegram.

هذه تجربة جامع RSS القديم، ولا تشغّل مسار البحث الحي للاهتمامات الموصوف أدناه. لا تُعرض بيانات وهمية كأخبار حقيقية، ولا تثبت التجربة شمول تغطية المصادر السورية.

### اختبار اهتمام حي من المتصفح محليًا

1. شغّل `npm run beta:local` من جذر المشروع. يبني الأمر نسخة Pages للاختبار ويجهز حسابًا تجريبيًا وقاعدة D1 محلية منفصلة داخل `.wrangler/personalized-beta`، دون Brevo أو جدولة أو قاعدة بعيدة. يستخدم نسخة مؤقتة منفصلة وإعدادات اختبار لتعطيل إرسال Telegram والاكتشاف الوهمي.
2. أبقِ الطرفية مفتوحة، وافتح الملف `.wrangler/personalized-beta/manage-url.txt` وانسخ الرابط المحلي منه إلى المتصفح. الرابط يخص حساب الاختبار المحلي فقط وينتهي بعد يوم، ويتغير عند إعادة تشغيل الأمر.
3. أضف اهتمامًا من صفحة الإدارة واضغط «اختبر الاهتمام الآن». تعرض الصفحة فقط النتائج ذات الروابط المباشرة والأدلة المتحققة؛ عند تعذر التحقق تعرض نتيجة فارغة مع أعداد البحث. لا يعني ذلك شمول المصادر السورية.
4. أوقف الخادم باستخدام Ctrl+C. يقتصر البحث الحي على المزود المجاني الحالي، وبحد أقصى 24 طلب شبكة لكل تشغيل، وثلاث عمليات لكل مشترك في الساعة و30 عملية عامة في الساعة؛ لا يرسل إشعارات Telegram.

لإعادة اختبار الاهتمامات الثلاثة المحددة دون تشغيل المتصفح: `node --use-system-ca scripts/live-interest-smoke.mjs`. يستخدم الاختبار قاعدة محلية في الذاكرة وعمليات بحث حقيقية محدودة، ويطبع النتائج والأخطاء كما وردت.

```bash
npm install          # تثبيت
npm run demo         # تجربة محلية تفاعلية
npm run dev          # تطوير محلي
npm run build        # فحص الأنواع + بناء
npm run deploy       # بناء + نشر إلى Pages
npm run db:schema    # تطبيق مخطط D1 (مرة واحدة)
```

## تجربة التسجيل المغلقة محليًا

شغّل `npm run beta:onboarding` وافتح `http://127.0.0.1:8788/beta`. أدخل اهتمامًا واضغط «المتابعة عبر Telegram»، ثم اختر «محاكاة تأكيد Telegram محليًا». يحاكي الزر التأكيد فقط ولا يتصل بـ Telegram أو قاعدة بعيدة. يمكن تجربة الإضافة والتعديل والإيقاف والإلغاء وتسجيل الخروج، ثم استخدام «لدي حساب بالفعل» للعودة. البيانات تبقى في قاعدة محلية معزولة في `.wrangler/beta-onboarding`. لإجراء فحص آلي أثناء تشغيل الخادم: `node scripts/beta-local-smoke.mjs`.

قبل أي تشغيل حقيقي لاحق، يحتاج المشغّل إلى تهيئة `TELEGRAM_BOT` وسرَيّ البوت والـ webhook وقائمة المعرّفات الرقمية المدعوة في `BETA_ALLOWED_TELEGRAM_IDS` (مفصولة بفواصل)، وHTTPS، وتطبيق الترحيل `0010` بعد نسخة احتياطية. `BETA_DURATION_DAYS` قابل للضبط من 1 إلى 365 ويكون 30 افتراضيًا. لا يُقبل حساب خارج القائمة، ولا تُفعّل الإشعارات للمشترك الجديد قبل موافقته. يبقى إرسال التنبيهات الفعلي محكومًا بإعدادات الأمان السابقة ولا يُفعّل هذا المسار النشرة القديمة للحسابات التجريبية الجديدة. تأكيد الدخول يتطلب مطابقة الرمز المرئي في المتصفح مع رسالة البوت والضغط على زر الموافقة في المحادثة الخاصة؛ لا توافق على طلب لم تبدأه بنفسك. لم يُختبر الربط الحقيقي أو يُنشر في هذه المهمة.

إلغاء الاشتراك يوقف التنبيهات ولا يحذف بيانات الحساب؛ طلب الحذف حاليًا إجراء يدوي لدى المشغّل. لا تُمثل المصادر القليلة المراقبة تغطية شاملة، واكتشافها ليس تلقائيًا بالكامل.

### اختبار تسليم التنبيهات الشخصية

`npm run test:beta-delivery` يشغّل اختبارات محلية معزولة، منها اختبار كامل لمحاكاة صفحة مصدر وفحصها وتخزين الخبر وتسليمه عبر Telegram وهمي. البيانات في هذا الاختبار اصطناعية وليست أخبارًا حقيقية، ولا يخرج أي طلب شبكة. يُشترط نشر العنصر ورصده بعد الموافقة على التنبيهات وبعد آخر تعديل للاهتمام، وأن يكون النشر خلال `BETA_FRESHNESS_HOURS` (72 ساعة افتراضيًا؛ من 1 إلى 168). التاريخ الناقص أو غير المحدد بوقت ومنطقة زمنية يُرفض. تبقى الأخبار الأقدم محفوظة للتحليل.

للتجربة الحقيقية لاحقًا وبعد تصريح منفصل: جهّز حسابين خاصين أكدا الربط والموافقة، وأدرج معرّفيهما في كل من `BETA_ALLOWED_TELEGRAM_IDS` و`TELEGRAM_TEST_CHAT_IDS`. بعد المراجعة والنسخ الاحتياطي والترحيل 0011، يستطيع المشغّل المصرّح له تفعيل `TELEGRAM_DELIVERY_ENABLED=1` واستخدام طلب إداري إلى `/api/notify` بحقول `mode: "deliver"`, و`beta_manual: true`, و`subscriber_id` واحد، واختياريًا `refresh_sources: true` لإعادة فحص الاهتمامات أولًا. لا يمكن لمفتاح cron وحده تشغيل مسار beta اليدوي، ولا يرسل النداء المجدول العام لحسابات beta الجديدة. لا تفعّل العامل المجدول لهذه التجربة. يظل خطر تكرار الرسالة قائمًا إذا توقف التنفيذ بعد قبول Telegram للإرسال وقبل تسجيل نجاحه، كما قد تؤخر حدود المصدر أو أخطاؤه اكتشاف تحديثات حقيقية.

## واجهات API

| المسار | الطريقة | الوظيفة |
|---|---|---|
| `/api/subscribe` | POST | تسجيل/تحديث اشتراك (تجربة 3 أيام تلقائية) |
| `/api/login` | POST | إرسال رابط دخول سحري |
| `/api/me?token=` | GET/PATCH/DELETE | عرض/تعديل/إلغاء الاشتراك |
| `/api/news` | GET | أخبار آخر 24 ساعة (عامة) |
| `/api/ingest` | POST | تجميع الأخبار (x-cron-secret) |
| `/api/digest` | POST | بناء وإرسال نشرات الساعة الحالية (x-cron-secret) |
| `/api/admin/login` | POST | دخول الإدارة |
| `/api/admin/subscribers` | GET/POST | قائمة المشتركين + الإحصاءات / تنفيذ إجراء |

## التوسع للمستوى الوطني — الخيارات

- **البريد**: Brevo (300/يوم مجاني) → Mailgun/SendGrid عند آلاف المشتركين
- **الواتساب**: WhatsApp Business API (~0.05$/محادثة، يتطلب توثيق Meta Business) — الواجهة جاهزة لعرضه "قريباً"
- **الدفع**: تفعيل يدوي الآن → USDT أو حوالات لاحقاً؛ Stripe غير متاح في سوريا
- **المصادر**: إضافة مصادر RSS سورية مباشرة، أو NewsAPI/GDELT عند الحاجة
- **النطاق**: dial-syria.pages.dev مجاني الآن → نطاق مخصص (~10$/سنة) يُربط من Dashboard → Custom domains
